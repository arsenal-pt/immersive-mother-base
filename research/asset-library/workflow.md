# Standing asset-reference workflow

Dedicated subsystem owner: the asset-library research subagent (`asset_library_planning`). Main chat coordinates scope, user decisions, review and publication. Recover the project checkpoint/memory/task records before starting; do not automatically resume another animation or asset batch.

1. Choose one small category and exact asset/variant IDs before source work. Keep completed/pending/remaining IDs and exclusions. Three pilot entries do not mean the category is complete.
2. Reuse verified retained private assets by default. New extraction, conversion, game testing or a separate full-game catalogue are separate scopes. Never distribute original game models, textures, archives, decoded geometry, blends or tool binaries.
3. Record actual source model/container paths and hashes while reading/extracting. Preserve exact case/path identity, original variants/LOD, sampler and texture hashes, tool versions/dictionary provenance when used, and evidence levels. Unknowns stay null. Historical outer origins are not fresh installed-archive proof.
4. Give every record a useful Category, semantic Tags and plain-English Description. Useful tags include asset type, material/appearance, environment/department and plausible use. Distinguish source namespace/recorded scene uses from unsupported exclusive origin or native interaction claims. Credits belong centrally and on detail/source pages, not browsing columns.
5. Produce one clean textured still and one complete 360-degree camera-orbit GIF per selected asset. Prefer white/light neutral or another contrasting background; keep full framing and fixed scale. Preserve clean images/frames privately before optional labels. Verify actual texture/UV choice; do not silently replace absent textures with guessed material colors.
6. Index pages have zero images. Default category tables have small static clickable thumbnails, at most 12rows/page. Larger still/GIF loads only on the selected asset page. Do not rely on collapsed sections to stop downloads. Reference budgets:768px still,480px/48-angle GIF,100 ms/frame,160px thumbnail; changes should be explicit and proportionate.
7. Review one sample before batching. End with one concise contact sheet, hashes of inputs/outputs, selected-LOD/texture checks, GIF frame/loop/duration validation, metadata/relative-link consistency and source/private-file exclusion. Offline rendering does not establish gameplay, collisions or FOX shader equivalence.
8. Exclude rendered media from software/release inventories; keep its own provenance manifest. Freeze scoped authored changes for root review before publication. Save canonical plan/task/decisions/devlog/memory plus exact private mirrors and a scoped local authored commit. Raw sources and clean frames stay private. Stop at the selected batch boundary.

See [the plan](RESEARCH-PLAN.md) for taxonomy, coverage limits and starter settings. A future separate reference project is possible but is not created here.
