# Standing asset-reference workflow

Dedicated subsystem owner: the asset-library research subagent (`asset_library_planning`). Main chat coordinates scope, user decisions, review and publication. Recover the project checkpoint/memory/task records before starting; do not automatically resume another animation or asset batch.

1. Choose one small category and exact asset/variant IDs before source work. Keep completed/pending/remaining IDs and exclusions. Three pilot entries do not mean the category is complete.
2. Reuse verified retained private assets by default. New extraction, conversion, game testing or a separate full-game catalogue are separate scopes. Never distribute original game models, textures, archives, decoded geometry, blends or tool binaries.
3. Record actual source model/container paths and hashes while reading/extracting. Preserve exact case/path identity, original variants/LOD, sampler and texture hashes, tool versions/dictionary provenance when used, and evidence levels. Unknowns stay null. Historical outer origins are not fresh installed-archive proof.
4. Give every record a useful Category, semantic Tags and plain-English Description. Useful tags include asset type, material/appearance, environment/department and plausible use. Distinguish source namespace/recorded scene uses from unsupported exclusive origin or native interaction claims. Credits belong centrally and on detail/source pages, not browsing columns.
5. Produce one clean textured still and one complete 360-degree camera-orbit GIF per selected asset. Prefer white/light neutral or another contrasting background; keep full framing and fixed scale. Preserve clean images/frames privately before optional labels. Verify actual texture/UV choice; do not silently replace absent textures with guessed material colors.
6. Index pages have zero images. Default category tables have small static clickable thumbnails, at most 12rows/page. Larger still/GIF loads only on the selected asset page. Do not rely on collapsed sections to stop downloads. Reference budgets:768px still,480px/48-angle GIF,100 ms/frame,160px thumbnail; changes should be explicit and proportionate.
7. Review one sample before batching. End with one concise contact sheet, hashes of inputs/outputs, selected-LOD/texture checks, GIF frame/loop/duration validation, metadata/relative-link consistency and source/private-file exclusion. Offline rendering does not establish gameplay, collisions or FOX shader equivalence.
8. Exclude rendered media from software/release inventories; keep its own provenance manifest. Freeze scoped authored changes for root review before publication. Save canonical plan/task/decisions/devlog/memory plus exact private mirrors and a scoped local authored commit. Raw sources and clean frames stay private. Stop at the selected batch boundary.

See [the plan](RESEARCH-PLAN.md) for taxonomy, coverage limits and starter settings. A future separate reference project is possible but is not created here.

## Source quality and duplicate handling

For each future expressly selected asset family, inventory actual retained/native model versions, native LOD face groups, texture dimensions and declared mip counts while reading its source. Record exact native paths/content hashes, LOD index identities/triangle counts and texture/header/DDS hashes. Compare actual source buffers before calling a level highest or reduced detail; do not assume every asset uses the same LOD numbering or that more triangles imply a better texture. Keep missing/unresolved variants explicit.

Deduplicate identical native model/geometry/texture content with source/LOD mappings rather than redundant renders. Show every distinct supported native geometric LOD in a small static comparison and lazy individual reference page; preserve accepted original previews and stable parent IDs. Hold verified base texture/camera/framing constant across mesh comparisons. Keep Quality/LOD and actual Base texture pixels/native mips as separate browsing columns and numeric fields in portable data. Record normal/specular/material channels separately from what the approximate preview shader actually uses.

Highest retained is a scoped finding, not an all-game maximum claim. Never fabricate higher quality through subdivision/upscaling or present invented downsampled maps as native alternatives. Preserve real native mip chains privately and catalogue them; do not render the Cartesian product of geometry LODs and texture mips. Runtime thresholds/native shaders require independent proof and are not recreated by a reference-catalogue task. Finish an expressly selected quality scope before silently starting other model families.


## Import an already generated local batch

Use import_batch.py on a reviewed portable pipeline export with explicit selected IDs and a fresh media prefix, then run build-library.py (or --check to verify the generated pages/CSV). The importer checks the export catalogue/media hashes, blocks escaped/private machine paths and conflicting accepted identities, copies only PNG/GIF reference media, and preserves existing parent records and previews. The seven reviewed labels are optional overrides. Other valid exported assets use sanitized pipeline titles, descriptions, categories and tags with conservative namespace/evidence fallback; no per-entry code edit is required. Import validates safe portable IDs/table paths and actual PNG/GIF dimensions/frame timing. Visual review remains a separate publication boundary, not automatic inference of behavior. Sampler names are carried only when exported; missing names remain explicitly unknown while actual path/binding hashes are retained.

The current imported set is seven selected references: five user-run models plus two earlier shelf proofs. Each has exactly one selected LOD0 still/turntable/thumbnail. Other native LOD counts/index hashes and duplicates are recorded with explicit unrendered status, rather than silently claiming every quality view was made. A source SHA/ID already present must be deduplicated; accepted seating media/detail pages stay byte-exact. Credits belong centrally/on detail pages, not in browsing columns. Public imports contain no raw model/texture/decoded cache/database with private operations. Keep future batches at the user's chosen size, retain clean private originals and freeze source/media/provenance for review before upload.

Do not replace unknown names, missing dependencies, unsupported assemblies or unrendered entries with guessed success. Metadata census and selected preview queues remain separate.
