# Animation library research plan

The current starter uses only the **25 already decoded and reviewed clips**. Their original extraction records and full-size previews are preserved. This work creates browsing pages, smaller animated thumbnails and portable metadata; it starts no new extraction, rendering batch or native test. The [library index](README.md) and [references](references.md) describe this starting set and additional discovery leads.

## Current phase

Phase 1 is the existing 25-clip starter: 11 Snake CQC/transition candidates, 8 NPC receiver candidates and 6 special/zombie candidates. Each has an exact archive/clip identity, original nested records, a larger GIF page and bounded animated/still tables. The root chat coordinates integration, review, publication and human decisions. Subagents implement only expressly assigned, bounded work and return evidence before another task is selected.

## Later selected batches

The following is a plan for future approval, not work started by this update:

1. The human/root selects one question and **3–5 exact clips**. Record archive, clip identifier/hash, source credit and source revision/hash before extraction. Guide or workbook names are leads until matched to actual game data. Do not import the whole workbook or automatically enumerate/extract all game animations.
2. Assign a bounded subagent task with selected IDs, copied inputs, output location, acceptance checks and stop condition. Preserve source originals, extracted payload hashes and historical confidence fields; use a fresh private lane for game data.
3. Prove one faithfully decoded full-character sample, preserve clean frames and ask for a focused human visual check when useful. Record the chosen preview speed separately from native timing and retain explicit blockers for unsupported clips.
4. Finish only the selected clips. Add titled GIFs, stills, complete metadata and archive/hash-based stable IDs. Keep the index image-free, animated tables at four GIFs or fewer, and a still-image alternative. Verify source preservation, relative links, media decode and deterministic output.
5. Return a short handoff with changed files, source/tool credits and revisions, input/output hashes, checks, practical limits, retained failures and the exact next action. Root reviews and publishes only the selected scope, then updates the project checkpoint, tasks, plan, decisions and history. Stop until another batch is expressly assigned.

Possible later topics include idle actions, locomotion, duties, services and reactions across MGSV. A separate library repository is a future option. No actor compatibility, paired contact, native FPS or gameplay behavior is established by an offline GIF; native integration remains a separately selected task. Keep raw game payloads, scenes and the supplied workbook private, and retain [AI and upstream credit](../../CREDITS.md) and [license scope](../../LICENSE-SCOPE.md).
