# Animation extraction and preview standard

New animation research should be immediately understandable to people who do not know the game's filenames. Each selected clip needs a titled looping GIF, a static thumbnail and a catalogue link when a faithful preview is supported. If playback cannot be reconstructed, retain its extracted entry with an explicit missing-preview status and the actual blocker.

## Procedure

1. Extract copies with the documented community tools. Preserve original packages, clip payloads, sidecars and layouts privately. Record exact clip identity, archive ownership, source hashes, tool versions and role confidence.
2. Establish one decoded-motion preview before a batch. Use a compatible rig, a full character mesh and a documented mapping. The project owner selected full-character previews after reviewing a skeleton sample; skeleton views remain diagnostics unless that preference changes. A dummy-track import or a plausible procedural movement is not a character animation preview.
3. Record the rig's author and revision, mapping identity, imported frame range, chosen preview frame rate and root-motion treatment. Keep native timing unconfirmed until measured in game. An offline rig preview is separate evidence from native gameplay.
4. Preserve clean source frames or video before adding text. Frame the whole action; keep camera, lighting and ground reference consistent across the set. Add a plain-English title and the exact clip identifier. Label attacker, receiver, transition and special-actor variants separately.
5. Save the titled GIF and static thumbnail with source/render hashes and technical metadata. Link both from the clip catalogue and use descriptive alt text in the research gallery. Keep rendered documentation media outside installable software packages.
6. Review one short sample before rendering the set. Human visual feedback is welcome: ask one focused question about an identified sample and record the answer in its tested context.
7. Account for every selected clip as previewed, distorted, unsupported or pending. Extraction and archive roundtrip checks establish data preservation; they do not prove retargeting, paired contact, root motion, timing or native actor compatibility.
8. Update the research guide, catalogue and provenance manifest. Preserve failed attempts and next actions. Credit community tools, reference rigs and original game assets explicitly. Publish authored recipes and reviewed rendered documentation within the authorized scope; raw game files and scenes containing them stay private.

## CQC combo set

Browse the [animation reference library](animation-library/README.md) for small paged previews, larger clip pages and complete data. Its [research plan](animation-library/RESEARCH-PLAN.md) keeps later work to explicitly selected 3–5-clip batches: root chat handles orchestration/human decisions and subagents implement only their assigned scope. Keep the index image-free, each animated table at no more than four GIFs, and a still-image alternative. Preserve stable archive/hash identities, exact original records and source credits; a guide or workbook name is a discovery lead rather than extraction or gameplay evidence.

The [MtarTool extraction catalogue](mtar-punch-combos/README.md) contains 25 selected entries. Its ordinary NPC combo family is the receiving side candidate, not a proven normal-soldier attacker combo. Any reference-rig GIFs must retain this distinction. Preview rates are presentation choices until native timing has been measured.

This workflow was requested by the project owner on 15 October 2026 as a standing requirement for continuing animation extraction/research, including work delegated to an AI agent. It does not by itself authorize a game installation, runtime experiment or new release.
